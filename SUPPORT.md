# Support

## Getting help

- **Bugs and behavior questions** — open a [GitHub issue](https://github.com/ghxrk13/gaige/issues).
- **Calibration questions, results discussion** — GitHub Discussions.
- **Security reports** — see `SECURITY.md`; never a public issue.
- **Commercial licensing and engagements** — see `COMMERCIAL.md`, or ghxrk13@proton.me.

## What makes a report answerable

gaige's own habit applies in reverse: a number without its instrument cannot be debugged.
The fastest route to a fix is the receipt —

1. the instrument fingerprint from the run (`env.json`, or `gaige --version` plus OS and
   Python version),
2. the exact command,
3. what it printed, next to what you expected.

A report that reproduces from a committed corpus or fixture gets fixed first.

## The honest part

This is a small project without a support organization behind it. Response is best-effort,
prioritized by severity and reproducibility; there are no SLAs. Anything that makes a
shipped number wrong or a refusal dishonest jumps the queue.

## Fuel

If gaige is useful to you, [ko-fi.com/gaigedev](https://ko-fi.com/gaigedev) funds GPU time
and corpora. Support never buys a different answer; credibility features are never paid.
